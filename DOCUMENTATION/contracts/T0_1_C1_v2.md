## 0. 🔴 Two defects found while enumerating — both are C1's business

### 0.1 The cache-identity fix is ONE LEVEL TOO SHALLOW

`_src_sha()` (`transport_srcpulse_demo.py:302`) folds **two** files into the cache identity: this module and
`model_io_utils.py`. Its docstring gives the reason, and the reason is right:

> *"An edit to grid generation changes this model just as surely as an edit here does, and without it that
> edit would leave every warm cache valid while the grid moved underneath it — the exact bug class this
> repo has already shipped once."*

**But `model_io_utils` does not build the mesh — it delegates.** `model_io_utils.py:2219,2223` call
`dgu.create_disv_from_boundary(...)` and `dgu.refine_grid_locally(...)`. **So an edit to
`disv_grid_utils.py` changes the refined mesh while every warm cache — student caches included — stays
valid.** The hole the fingerprint exists to close is still open one level down.

**C1 records this as a KNOWN DEFECT and T1 must fix it**: the fingerprint covers the *transitive* local
module closure of the model build (§1.2), not a hand-picked pair. Hand-picking is what left the gap.

### 0.2 `transport_base_model.py` is a CHANGE surface but not a DEPENDENCY surface

Nothing in the transport track imports it. All three apparent references are **docstring mentions**
(`transport_verify_2d.py:26`, `transport_srcpulse_demo.py:28`, `transport_prt_capture.py:150`). Yet it
holds a **duplicate `courant_nstp`** (`:146`) that T1 must canonicalise, and a **replicated copy of
`LOCKED_PARAMS`** (`transport_srcpulse_demo.py:55` says so outright).

⚠️ **Divergence hazard, recorded:** editing `LOCKED_PARAMS` in `transport_base_model` has **no effect** on
the notebooks, and editing the replica has no effect on `transport_base_model`. A future maintainer
changing "the locked parameters" can silently change only half the track.
